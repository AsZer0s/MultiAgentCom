# MultiAgentCom 细化需求文档（Refined Spec v0.1）

> 本文基于 `docs/Spec.md` 进行工程化细化，用于指导 MVP 设计、研发拆解与验收。

## 1. 文档目的与范围

### 1.1 目的
- 将愿景型描述落地为可实现的系统需求。
- 明确系统边界、核心流程、模块职责与验收标准。
- 作为产品、架构、研发、测试的单一事实来源（SSOT）。

### 1.2 范围
- 覆盖多智能体协同开发平台的核心能力。
- 覆盖 HITL（人类在环）、沙盒隔离、版本时空机制、可观测性。
- 覆盖 MVP 到后续阶段的里程碑拆解。

### 1.3 非范围（当前版本）
- 不定义具体 UI 视觉稿与品牌规范。
- 不限定底层模型厂商与 API 供应商。
- 不包含计费、组织权限、企业审计的完整商业化细节（后续版本补充）。

## 2. 系统定位与价值主张

### 2.1 系统定位
MultiAgentCom 是一个“主控调度 + 专职子 Agent”协同的软件研发平台，面向从需求到交付的全流程自动化开发。

### 2.2 核心价值
- **效率提升：** 通过并行子 Agent 缩短交付周期。
- **质量提升：** 通过契约先行、测试闸门、回滚机制降低缺陷率。
- **可控性：** 通过 HITL 实现关键节点接管与强制纠偏。
- **可追溯性：** 通过语义快照与可视化监控实现全链路可解释。

## 3. 角色定义

- **人类开发者（Owner）**
  - 输入需求、审阅计划、在关键节点接管。
  - 锁定 Ground Truth 代码与策略。
- **Manager Agent（主控）**
  - 需求反刍、任务分解、上下文切片、调度子 Agent。
  - 管理契约、发布指令、聚合产物、驱动验收。
- **Worker Agents（子 Agent）**
  - 按领域完成实现任务（如后端、前端、数据、测试）。
  - 在私有沙盒执行开发与本地验证。
- **System Runtime（平台运行时）**
  - 提供沙盒、版本、日志、可视化、产物管理能力。

## 4. 端到端主流程

### 4.1 流程阶段
1. **需求输入**
2. **PRD 反刍与澄清**
3. **契约定义（API/Schema）**
4. **任务拆解与上下文分发**
5. **并行开发（私有沙盒）**
6. **产物提交（共享沙盒）**
7. **集成测试与验收预览**
8. **人类确认与交付打包**

### 4.2 状态机（任务级）
- `CREATED` -> `PLANNING` -> `IN_PROGRESS` -> `WAITING_REVIEW` -> `MERGED` -> `DONE`
- 失败分支：`IN_PROGRESS` / `WAITING_REVIEW` -> `FAILED` -> `REWORK`
- 人类介入：任意状态 -> `HUMAN_OVERRIDE` -> 回到 `IN_PROGRESS` 或 `DONE`

### 4.3 阶段产物
- 需求阶段：PRD 文档
- 契约阶段：OpenAPI / 数据模型定义
- 开发阶段：代码产物与测试报告
- 验收阶段：可运行预览、验收记录
- 交付阶段：源码包、部署脚本、README

## 5. 功能需求（FR）

### FR-01 需求反刍与 PRD 生成
- 系统应支持从用户输入自动生成结构化 PRD。
- 系统应支持多轮澄清问题并记录决策依据。
- 生成 PRD 应至少包含：目标、范围、约束、验收标准。

### FR-02 契约优先（Contract First）
- 系统应在编码前生成 API 与数据结构契约。
- 契约应可版本化，并可被各子 Agent 读取。
- 若实现与契约冲突，系统应阻止合并并触发修复流程。

### FR-03 动态路由与子 Agent 实例化
- Manager 应基于任务类型/复杂度选择子 Agent 角色。
- 系统应支持并行任务下发与依赖编排。
- 系统应支持失败重试与替补 Agent 策略。

### FR-04 精准上下文注入
- Manager 应将全局上下文按角色切片后分发。
- 子 Agent 默认不可读取无关上下文（降低噪音与 Token 成本）。
- 每次注入应可追踪版本与来源。

### FR-05 双层沙盒机制
- 每个子 Agent 必须在私有沙盒执行构建、测试与试错。
- 仅通过验证的产物可进入共享沙盒。
- 共享沙盒集成失败时应支持一键回滚到上一个稳定状态。

### FR-06 深度 HITL
- 人类可在任意阶段插入高优先级指令。
- 人类可标记代码为 `LOCKED BY HUMAN`，系统不得自动覆盖。
- 系统应支持“非阻塞注入”：新需求在安全检查点生效。

### FR-07 语义快照与时间线管理
- 系统应在关键节点自动生成语义快照。
- 回滚不覆盖历史，而是创建平行分支时间线。
- 回滚后系统应强制清理已失效上下文记忆。

### FR-08 可观测性与可视化
- 实时展示各 Agent 状态与任务进度。
- 展示跨 Agent 依赖拓扑与产物流向。
- 支持查看内部通信日志与 Token 消耗趋势。

### FR-09 预览与交付
- 合并后自动启动预览环境并支持热更新。
- 通过验收后自动生成标准工程化交付物。
- 交付物至少包含：依赖声明、部署脚本、README。

## 6. 非功能需求（NFR）

### NFR-01 性能
- 支持多 Agent 并发执行，调度延迟可控。
- 关键页面（状态面板）应提供近实时刷新能力。

### NFR-02 可靠性
- 沙盒崩溃不得影响主流程与其他 Agent。
- 所有关键操作（调度、合并、回滚）需具备幂等设计。

### NFR-03 安全性
- 私有沙盒与共享沙盒必须物理/逻辑隔离。
- 人类锁定代码块需具备不可覆盖保障。
- API 鉴权令牌需支持通过环境变量配置并在 MVP 中以单租户模式运行。

### NFR-04 可追溯性
- 所有决策、指令、合并、回滚均需可审计。
- 任一产物需追溯到任务、Agent、契约与快照。
- 关键失败事件需可被查询，并支持最小主动通知出口。

### NFR-05 可扩展性
- Agent 类型应可插件化扩展。
- 通信协议应支持版本演进与向后兼容策略。

## 7. 核心模块与职责

- **Orchestrator（编排调度）**
  - 任务分解、依赖图、优先级与重试策略。
- **Context Engine（上下文引擎）**
  - 文档切片、角色过滤、注入版本管理。
- **Contract Hub（契约中心）**
  - API/Schema 管理、校验、差异比对。
- **Sandbox Runtime（沙盒运行时）**
  - 私有执行环境、共享集成环境、回滚控制。
- **HITL Console（人工控制台）**
  - 接管、纠偏、锁定、增量需求注入。
- **Timeline Engine（时间线引擎）**
  - 语义快照、分支切换、记忆重组广播。
- **Observability（观测系统）**
  - 状态矩阵、拓扑图、通信与 Token 监控。
- **Delivery Engine（交付引擎）**
  - 预览环境、打包构建、部署脚本生成。

## 8. 数据与对象模型（草案）

### 8.1 核心实体
- `Project`: 项目元信息与全局配置
- `Requirement`: 需求输入与澄清记录
- `Contract`: 接口/模型契约与版本
- `Task`: 可执行研发任务单元
- `AgentRun`: 子 Agent 运行实例
- `Artifact`: 代码/文档/测试产物
- `Snapshot`: 语义快照与分支信息
- `HumanOverride`: 人类干预事件

### 8.2 关键关系
- `Project` 1-N `Requirement`
- `Requirement` 1-N `Task`
- `Task` 1-N `AgentRun`
- `AgentRun` N-N `Artifact`
- `Task` N-1 `Contract`（可多版本映射）
- `Project` 1-N `Snapshot`

## 9. 内部通信协议（草案）

### 9.1 设计原则
- 结构化优先，禁止自由散文式长文本同步。
- 短消息、高频次、可校验、可追踪。
- 协议必须包含版本字段。

### 9.2 建议消息结构
```json
{
  "version": "v1",
  "from": "python-agent",
  "to": "go-agent",
  "type": "SYNC_SCHEMA",
  "taskId": "task_123",
  "payloadRef": "artifact://schema/8f9a",
  "checksum": "8f9a",
  "timestamp": "2026-04-09T00:00:00Z"
}
```

### 9.3 协议验收标准
- 无版本号消息不得被消费。
- checksum 校验失败消息必须丢弃并重拉。
- 每条跨 Agent 消息可追踪至 taskId 与 artifact。

## 10. MVP 拆解与里程碑

### M1（最小闭环）
- 需求输入 -> PRD 生成 -> 任务拆解 -> 单 Agent 执行 -> 产物导出
- 目标：跑通最短交付链路

### M2（协同能力）
- 多 Agent 并行、契约中心、上下文切片、基础状态面板
- 目标：实现稳定并行协作

### M3（安全与可控）
- 双层沙盒、回滚、HITL 接管与代码锁定
- 目标：提升可控性与恢复能力

### M4（工程化交付）
- 预览环境、热更新、标准化打包、交付模板
- 目标：形成可直接落地的交付体验

## 11. 验收标准（全局）

- 能在一个示例项目中完成从需求到交付的全流程。
- 至少支持 2 类异构子 Agent 协同（如后端 + 前端）。
- 人类可在中途接管并锁定代码，后续流程不覆盖锁定内容。
- 集成失败可回滚到最近稳定快照并继续推进。
- 最终产物可本地一键运行（含基础 README 与部署脚本）。

## 12. 风险与缓解

- **上下文漂移风险：** 通过契约校验 + 快照回放 + 注入最小化缓解。
- **多 Agent 竞争冲突：** 通过任务依赖图与合并前静态检查缓解。
- **成本失控（Token/算力）：** 通过结构化通信与上下文裁剪缓解。
- **人机协作断层：** 通过 HITL 检查点与变更可视化缓解。
