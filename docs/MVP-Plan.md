# MultiAgentCom MVP 实施计划（v0.1）

> 本文对应 `docs/Spec-Refined.md`，用于将 M1-M4 里程碑转为可执行计划、排期与交付清单。

## 1. 计划目标

- 在 8 周内完成可演示的 MVP 主链路。
- 达成“需求到交付”的闭环，并具备基础协同与可控能力。
- 保证每个阶段有明确可验收产物与退场条件（Exit Criteria）。

## 2. 迭代节奏

- 建议采用 4 个 Sprint，每个 Sprint 2 周。
- 每个 Sprint 固定节奏：
  - 第 1-2 天：需求冻结与技术方案确认
  - 第 3-8 天：实现与联调
  - 第 9 天：测试与缺陷收敛
  - 第 10 天：验收演示与复盘

## 3. 里程碑规划（8 周）

## Sprint 1（周 1-2）：M1 最小闭环

### 目标
- 跑通最短链路：需求输入 -> PRD -> 任务拆解 -> 单 Agent 执行 -> 产物导出。

### 范围映射
- FR-01、FR-03（单 Agent 子集）、FR-09（导出子集）

### 核心任务
- 搭建项目骨架与最小后端服务。
- 实现需求输入接口与 PRD 生成流程。
- 实现单 Agent 执行器（串行模式）。
- 定义 `Task`、`AgentRun`、`Artifact` 最小数据结构。
- 实现基础产物导出（源码包 + README 模板）。

### 交付物
- 可运行 Demo（CLI 或 Web 最简入口）
- PRD 生成样例 3 份
- 任务执行日志与产物导出样例

### Exit Criteria
- 能基于一个示例需求生成 PRD 并产出可下载交付包。
- 任务状态可从 `CREATED` 流转到 `DONE`。

## Sprint 2（周 3-4）：M2 协同能力

### 目标
- 实现多 Agent 协同、契约优先与精准上下文分发。

### 范围映射
- FR-02、FR-03、FR-04、FR-08（基础面板）

### 核心任务
- 实现 Contract Hub（契约创建、版本管理、校验）。
- 实现并行调度（至少 2 个异构 Agent）。
- 实现 Context Engine（按角色切片注入）。
- 实现状态矩阵面板（最小版）与任务进度追踪。

### 交付物
- OpenAPI/Schema 契约样例
- 双 Agent 并行任务演示录像或脚本
- 状态面板最小可视化页面

### Exit Criteria
- 前后端双 Agent 可基于同一契约并行产出并通过合并前校验。
- 能看到各 Agent 的状态与任务进度。

## Sprint 3（周 5-6）：M3 可控与恢复

### 目标
- 完成双层沙盒、失败回滚与 HITL 核心能力。

### 范围映射
- FR-05、FR-06、FR-07

### 核心任务
- 实现私有沙盒与共享沙盒的最小隔离运行时。
- 实现集成失败自动回滚到最近稳定快照。
- 实现 HITL 指令注入与 `LOCKED BY HUMAN` 保护机制。
- 实现语义快照记录与平行分支时间线。

### 交付物
- 回滚演示用例（失败 -> 回滚 -> 重试成功）
- 人工锁定代码示例与保护验证记录
- 快照与时间线查询接口

### Exit Criteria
- 任一 Agent 在私有沙盒失败不影响其他 Agent 运行。
- 人类锁定代码后自动流程无法覆盖该片段。

## Sprint 4（周 7-8）：M4 预览与工程交付

### 目标
- 建立验收预览与标准化交付闭环，形成对外演示版本。

### 范围映射
- FR-08、FR-09（完整版）

### 核心任务
- 实现预览环境启动与基础热更新机制。
- 完成交付引擎：`go.mod`/`package.json`/`docker-compose.yml`/`README` 生成。
- 补齐可观测性：依赖拓扑、通信日志、Token 趋势图（最小可视化）。
- 进行端到端压测与稳定性测试（MVP 级）。

### 交付物
- 可点击验收预览环境
- 一键打包产物
- MVP 演示脚本（10 分钟）

### Exit Criteria
- 从需求输入到可运行交付包可在一次流程中完成。
- 演示脚本可稳定重复执行至少 3 次。

## 4. 工作分解结构（WBS）

- **WBS-01 基础平台**
  - 配置管理、日志、任务状态机、错误码。
- **WBS-02 Agent 编排层**
  - 调度器、队列、重试、并行执行。
- **WBS-03 上下文与契约层**
  - 文档切片、契约管理、一致性校验。
- **WBS-04 沙盒与时间线**
  - 私有/共享沙盒、快照、回滚、分支。
- **WBS-05 HITL 控制台**
  - 注入、纠偏、锁定、审计轨迹。
- **WBS-06 可观测与交付**
  - 状态面板、拓扑、通信日志、打包导出。

## 5. 优先级（MoSCoW）

### Must
- FR-01、FR-02、FR-03、FR-05、FR-06、FR-09

### Should
- FR-04、FR-07、FR-08（基础版）

### Could
- Token 趋势智能分析、自动性能建议、可视化高级筛选

### Won't（MVP 阶段不做）
- 企业级 RBAC、计费系统、多租户隔离、完整插件市场

## 6. 团队分工建议

- **产品/架构（1 人）**
  - PRD、里程碑管理、验收口径。
- **后端（2 人）**
  - 编排、契约、沙盒、时间线、交付引擎。
- **前端（1 人）**
  - 状态面板、HITL 控制台、预览页。
- **测试/QA（1 人）**
  - 验收用例、回归测试、稳定性报告。

## 7. 质量门禁（DoD）

- 单元测试通过率 >= 80%（MVP 基线）。
- 核心链路必须有端到端测试用例覆盖。
- 所有 FR 必须有对应验收用例 ID。
- 文档齐备：接口说明、部署说明、已知限制。

## 8. 风险与应对

- **并行调度复杂度超预期**
  - 先实现串行回退模式，保障可用性优先。
- **模型结果不稳定**
  - 引入契约校验和输出模板约束，失败重试。
- **沙盒成本偏高**
  - 优先实现轻量隔离方案，后续替换更强方案。
- **需求频繁变更**
  - 使用检查点机制，变更只在安全节点注入。

## 9. 度量指标（MVP）

- 端到端平均交付时长（目标：< 30 分钟/小型需求）。
- 一次通过率（目标：>= 60%）。
- 回滚恢复时长（目标：< 2 分钟）。
- 人类接管后恢复推进成功率（目标：>= 90%）。

## 10. 立即行动清单（本周）

- 确认 Demo 场景：Todo 全栈（后端 API + 前端页面）。
- 冻结 Sprint 1 的 API 与数据模型最小集合。
- 建立任务模板：`Task` + `Artifact` + `Snapshot`。
- 输出首版验收用例（见 `docs/Acceptance-Cases.md`）。
