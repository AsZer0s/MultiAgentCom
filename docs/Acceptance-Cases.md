# MultiAgentCom 验收用例（MVP v0.1）

> 用例与 `docs/Spec-Refined.md` 对齐，采用“场景-步骤-预期结果”结构，可用于手工验收或自动化改写。

## 1. 说明

- 用例 ID 格式：`AC-XX`
- 优先级：P0（必须）、P1（重要）、P2（可选）
- 结果判定：`PASS` / `FAIL`
- 覆盖范围：FR-01 ~ FR-09（MVP 关键路径）

## 2. 验收环境

- 运行环境：本地或测试服务器
- 示例项目：Todo 全栈（前端 + 后端）
- 数据准备：默认初始化样例需求、契约模板、测试账号

## 3. 用例清单

### AC-01 需求输入并生成 PRD（FR-01）【P0】

**前置条件**
- 系统可访问。

**步骤**
1. 输入需求：“实现 Todo 列表的增删改查”。
2. 点击开始分析。
3. 等待系统完成 PRD 生成。

**预期结果**
- 生成结构化 PRD，包含目标、范围、约束、验收标准。
- 系统记录澄清问题与决策摘要。

---

### AC-02 多轮澄清并更新 PRD（FR-01）【P0】

**前置条件**
- 已完成 AC-01。

**步骤**
1. 在澄清阶段新增限制：“后端使用 Go，前端使用 Vue”。
2. 提交澄清回答。
3. 查看 PRD 更新结果。

**预期结果**
- PRD 自动更新并保留变更记录。
- 技术栈约束出现在 PRD 的“约束”章节。

---

### AC-03 契约先行生成（FR-02）【P0】

**前置条件**
- PRD 已确认。

**步骤**
1. 触发“生成契约”操作。
2. 查看 OpenAPI/Schema 文档。

**预期结果**
- 成功生成至少 1 份 API 契约与 1 份数据模型定义。
- 契约具备版本号（例如 `v1`）。

---

### AC-04 契约冲突阻止合并（FR-02）【P0】

**前置条件**
- 已有契约 `v1`。
- 子 Agent 产物中故意引入字段不一致。

**步骤**
1. 提交与契约冲突的产物到共享沙盒。
2. 触发合并流程。

**预期结果**
- 合并被拒绝。
- 系统返回明确冲突信息并创建修复任务。

---

### AC-05 动态路由并行执行（FR-03）【P0】

**前置条件**
- 系统支持至少两个子 Agent（后端/前端）。

**步骤**
1. 发起包含前后端任务的需求。
2. 观察调度结果。

**预期结果**
- Manager 自动拆解任务并分配给两个子 Agent。
- 两个任务可并行执行并生成各自产物。

---

### AC-06 精准上下文注入（FR-04）【P1】

**前置条件**
- 已存在全局 PRD 与契约文档。

**步骤**
1. 查看后端 Agent 接收上下文。
2. 查看前端 Agent 接收上下文。

**预期结果**
- 后端 Agent 收到 API 与数据模型相关上下文。
- 前端 Agent 收到 UI 与交互相关上下文。
- 两者均记录注入版本与来源。

---

### AC-07 私有沙盒隔离（FR-05）【P0】

**前置条件**
- 两个子 Agent 同时运行。

**步骤**
1. 在 Agent-A 私有沙盒中执行一个故障脚本。
2. 观察 Agent-B 与主流程状态。

**预期结果**
- Agent-A 失败被隔离。
- Agent-B 与主流程继续运行，不受污染。

---

### AC-08 共享沙盒失败回滚（FR-05, FR-07）【P0】

**前置条件**
- 存在最近稳定快照。

**步骤**
1. 合并一个会导致集成测试失败的产物。
2. 触发集成流程。

**预期结果**
- 集成失败后自动回滚到稳定快照。
- 回滚事件被记录，可追溯。

---

### AC-09 HITL 强制接管（FR-06）【P0】

**前置条件**
- 子 Agent 正在执行任务。

**步骤**
1. 人类发出高优先级纠偏指令。
2. 查看任务执行轨迹。

**预期结果**
- 任务进入 `HUMAN_OVERRIDE`。
- 子 Agent 在下一安全点应用新指令继续执行。

---

### AC-10 人类锁定代码不可覆盖（FR-06）【P0】

**前置条件**
- 人类已在关键代码添加 `LOCKED BY HUMAN` 标识。

**步骤**
1. 触发后续自动重构任务。
2. 检查锁定代码片段。

**预期结果**
- 自动流程不覆盖锁定片段。
- 系统记录“跳过覆盖”日志。

---

### AC-11 语义快照与平行分支（FR-07）【P1】

**前置条件**
- 系统已运行多个任务周期。

**步骤**
1. 手动回滚到历史快照。
2. 再次发起新任务。

**预期结果**
- 产生新的时间线分支，而非覆盖原历史。
- 原分支与新分支均可查询与切换。

---

### AC-12 状态矩阵与拓扑可视化（FR-08）【P1】

**前置条件**
- 至少 2 个子 Agent 在运行。

**步骤**
1. 打开状态面板。
2. 查看依赖拓扑与任务流向。

**预期结果**
- 能看到各 Agent 状态（运行/阻塞/空闲）。
- 能看到 Manager -> Worker -> QA 的依赖链路。

---

### AC-13 内部通信日志可追踪（FR-08）【P1】

**前置条件**
- 已发生跨 Agent 通信。

**步骤**
1. 打开通信日志页面。
2. 按 taskId 过滤消息。

**预期结果**
- 日志包含 `version`、`from`、`to`、`taskId`、`checksum`。
- 可按 taskId 快速定位对应通信链路。

---

### AC-14 预览环境可验收（FR-09）【P0】

**前置条件**
- 代码已合并到共享沙盒。

**步骤**
1. 点击“启动预览”。
2. 在预览中完成 Todo 的新增、编辑、删除操作。

**预期结果**
- 预览环境可访问。
- 核心交互可用，且改动可热更新（如系统支持）。

---

### AC-15 标准化交付打包（FR-09）【P0】

**前置条件**
- AC-14 通过。

**步骤**
1. 触发“生成交付包”。
2. 下载并检查产物结构。

**预期结果**
- 产物包含 `go.mod` 或 `package.json`、`docker-compose.yml`、`README.md`。
- 按 README 可本地一键启动示例项目。
